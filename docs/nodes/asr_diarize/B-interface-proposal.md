## 1. 可直接发给团队的提案正文

我负责 B：本地/登记链接输入、素材登记、英文转写、说话人标签、全片时间轴，以及 CLI 输入与参数解析。

建议我们先统一一份 `transcript.json`。每个短片段保留规划中约定的 `segment_id、speaker_id、start_ms、end_ms、en`；时间使用从原视频起点计算的整数毫秒。同一份转写里，后续翻译、审核、配音和字幕都引用同一个片段 ID，不自行改动英文原文和时间。

60–90 秒的翻译块单独记录为 `chunks`，通过片段 ID 引用短片段，不直接变成一条长字幕或一个长配音窗口。上下文只作为参考，不重复生成字幕和音频。

B 提供输入解析与预处理函数；F 调用这些函数接入主图，并负责任务 ID、检查点、调度、恢复和最终状态。C 返回译文和审核问题，D 返回实际配音时长及超时反馈，E 使用固定时间轴生成字幕和发布包。我们各自完成模块自测后再交给 F 集成。

第一轮先交付人工模拟分段和异常样例，让大家不等模型就能联调；同时准备真实模型与授权素材。第二轮换成真实 ASR 和说话人区分，沿用相同的输出结构。模拟结果会明确标为 mock，不计入真实识别效果。

希望 F 与 C/D/E 先确认以下约定；有修改集中到同一份文档，避免各自写一套格式。

## 2. 建议冻结的关键约定

| 项目 | 提案 |
|---|---|
| 共享格式 | UTF-8 JSON；模型结构可由 F 用 Pydantic 实现，但 B 不先另建竞争版本 |
| 时间 | 全片整数毫秒；音频归一化前先校正容器/音轨起点差异；禁止删除静音后直接沿用局部时间 |
| 短片段 | 一段仅一个说话人；ID 在同一转写版本与下游返工中稳定 |
| 翻译块 | 按自然句边界聚合，目标 60–90 秒；尾块可更短；不得重复或遗漏输出片段 |
| 说话人 | 全片稳定标签；未确定使用 null 并记录问题，不强行猜测 |
| 结果版本 | `schema_version` 表示格式版本，`transcript_revision` 表示本素材转写版本 |
| 模拟/真实 | 显式 `mode`，同一结构；模拟与真实缓存隔离 |
| 返工 | C 修改中文；D 提供时长反馈；F 路由。修正英文/边界时另开转写版本并使相关下游失效 |
| 未解决问题 | 诊断产物可保存；仍有阻断问题时不能生成正式发布包 |
| 链接 | 仅支持登记的 YouTube ID → 有权读取的 HTTPS 原片地址；不承诺任意链接下载 |
| CLI | B 解析；F 执行与恢复；最终候选入口 `python -m localizer run/resume` |

## 3. 模块交付与接收

| 对接方 | B 提供 | 对方确认 |
|---|---|---|
| F | 解析后的命令、素材清单、标准转写、异常结构、自测记录 | 共享模型、主图函数签名、目录、缓存与恢复规则 |
| C | 英文片段、翻译块、前文引用、待复核提示 | 返回同一 ID 集合的译文；审校问题可定位到具体片段 |
| D | 全片说话人、每段窗口、归一化音频信息 | 音色映射及真实音频时长；超时反馈格式 |
| E | 原片引用、媒体时长、英文片段与时间 | 字幕时间映射、音视频合成与发布包输入 |
| A/G | 输入输出示意、实际问题、已测结果和日志节选 | 演示解释准确；人工样例不写成模型实测 |

## 4. 第一轮验收提议

1. 人工样例覆盖两人交替发言、静音间隔、两个翻译块和首尾时间；全组使用同一个样例。
2. C/D/E 能读取 B 的 JSON，不需要私自改名或换算单位。
3. 故意重复 ID、制造时间倒置、漏译一段时，校验能够定位问题。
4. F 能用模拟节点展示审校退回、配音超时退回及中断恢复；明确哪些结果被复用。
5. 真实阶段另验收媒体读取、ASR 文字、词/句时间与说话人交接，不能用结构通过代替准确性验证。

## 5. 请团队集中确认的事项

- F：是否采用所附共享结构和候选函数；共享模型由谁落地、放在哪个模块？
- C：是否接受固定片段 ID，块内多句一起理解、逐段返回中文；超长句怎样反馈？
- D：是否接受 `end_ms - start_ms` 作为默认配音窗口；按段合成还是按连续同人短语合成？本版先提议按段。
- E：是否接受片段时间固定，字幕内部换行由 E 处理；需要跨段重排时先返回请求？
- F/B：下载资源上限、重试上限、真实任务预算和时间上限在哪里配置？未填写时不启动长任务。

讨论后由 F 汇总结论，与受影响模块共同审核并发布接口版本。本文件不是代替团队确认的命令，也未触发任何远程消息或 Issue 操作。
