# tts_align：统一配音时序与恢复策略

当前说明更新于 2026-11-18。节点入口仍为 `nodes.tts_align.tts_align(state)`，仅由 F 的现有主图调用；没有增加业务图、GraphState 字段或依赖。

## 唯一规则来源

`project/nodes/dubbing_timing.py` 集中提供：

| 入口 | 职责 |
|---|---|
| `DubbingPolicy.from_plan` | 从 D 配置读取常规速度、延迟、返工轮数和耗尽策略 |
| `reserve_end_limits` | 在调用配音服务前检查全组时间轴，为每个后续组保留正时长 |
| `schedule_group` / `schedule_segment` | 自然组与逐片段共用时间窗规则，限制视频片尾及前向延迟 |
| `member_frame_cuts` | 将成员切点映射到最终PCM帧，所有成员非空且完整覆盖组音频 |
| `validate_final_timeline` | 发布前验证最终组顺序、无重叠、无越过片尾 |
| `validate_display_cues` | 字幕写出前检查最终时间及英文原文覆盖 |

原英文时间是不可修改的来源参考。最终播放位置由实测配音时间决定，字幕在最后按最终音频生成。不能拿原英文成员时间直接切已经压缩的PCM。

## 当前配置与终止规则

`config/tts.toml`：`duration_repair_attempts=8`、`duration_exhaustion_policy="use_latest"`，常规速度0.95–1.35、最大前向顺延500ms。

1. 前面各轮按实测时长改稿，审查被拒也占轮数；拒绝理由反馈到下一轮。
2. 达到第8轮，直接采用最后有效返工稿，停止D的英文一致性及数字保留审查，不回退早期稿。缓存次数累计，续跑不能重新获得8轮。
3. 耗尽后保持原视频时长，必要时允许超过1.35倍加速；放慢下限仍为0.95，不裁语音句尾。
4. 标记 `semantic_review_skipped_after_limit`，不能将这类结果称为语义审查通过；空稿、错误组ID、损坏或空音频仍报错。
5. 旧 `use_best` 和 `error` 配置保留兼容。缺省是error，当前项目明确选择use_latest。

C的定向返工仍通过repaired_blocks传给D；这项耗尽策略只控制D内部的时长改稿，不改变C和主图。

## 时间与音频的统一处理

先计算所有组的最终可用截止时间，再逐组安排配音。前组可在延迟限额内借时，但不能耗尽后组；片尾剩余窗口短于原英文跨度时允许压缩，而不是提前抛延迟异常。

逐段WAV仅保持既有产物契约，切点按最终组PCM映射；组装dub.wav直接使用完整组音频，避免成员片段毫秒舍入引入空隙。字幕仍通过最终配音识别/波形定位，不把成员PCM切点冒充精确字幕词对齐。

## 产物与诊断

- `audio/dub.wav`：纯中文，保持视频长度；混音由后续mix_background生成。
- `tts/clips.json`、逐段WAV：现有共享产物，未改变模型。
- `tts/dubbing_script.json`：最终实际使用稿件。
- `tts/alignment_report.json`：实际起止、原时间参考、倍速和成员PCM切点。
- `tts/*.speed.json`：实测变速回执。
- `tts/duration_repair_requests.json`：请求次数、候选稿、拒绝理由及采用策略。
- `tts/duration_fallback_warnings.json`：耗尽继续、跳过语义审查及速度例外，须回听。

以上辅助JSON仅为节点私有诊断，不新增跨组必需输入。原片只读，环境密钥和音色账户记录不提交GitHub。复刻音色需当前视频授权；本地音色匹配及自动准备逻辑不因本次时序集中修复改变。

## 字幕侧的配套规则

非法标点切点、改写原文、错误组ID、无效JSON或可选语义服务不可用时，丢弃模型切法，按完整原中英文执行本地单行分页；不增加收费重试、不改英文、不改变配音分组。合法组照常使用建议。最终时间必须在音轨及视频内，英文完整覆盖。见 [字幕节点说明](../subtitle_cover/README.md)。

## 已知失败样例与验证

- 第24组：前组借时324ms后，片尾剩4596ms；不再强制其等于原英文4840ms。已有6380ms语音在模拟耗尽后约1.397倍完整放入窗口。
- 第12组：原跨度5500ms压成5340ms，原成员切点5420ms会越界；现在按最终PCM映射，切片拼接逐字节还原整组。
- 新增组合反例：连续借时后遇到短应答、片尾收尾、语义拒绝耗尽、量化零时长、字幕建议服务失败及英文被模型改写。

两分钟失败任务已通过F主图的缓存重放：24组已有音频，重新变速/对齐、本地字幕ASR、混音及压制；120秒成片、42屏中英各一行，0字幕重叠、0越界、0新增收费调用。该验证将耗尽条件模拟为零轮，未实际执行8轮收费改稿；B/C和语音内容复用已有结果，不是重新全量推理。测试通过不等于音色自然度、语义和口型已经人工确认。

完整快速回归：586通过、2跳过、4项慢测未选、11个subtests通过（21.33秒）；另上述真实缓存重放1项通过（62.27秒）。

验证文件位于本机 `tests/tmp/unified-cached-replay-20261118/`，失败任务原产物未改动。重放测试为 `tests/smoke/test_cached_dub_replay.py`，是测试入口，不是第二张业务图。

复现：先具备本地模型与项目依赖，再设置 `LOCALIZER_REPLAY_JOB` 为已有失败任务目录，运行 `uv run --no-sync pytest tests/smoke/test_cached_dub_replay.py -q -s`。测试缺少缓存就停止，禁止新配音、翻译或音色创建；所有输出在tests/tmp，不上传。
