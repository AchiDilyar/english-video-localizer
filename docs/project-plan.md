# 基于多智能体协作的英文视频本地化系统｜整体项目规划书

- **课程**　同济大学《大模型与智能体技术》
- **周期**　10 天，从组内启动当天记为 D1
- **团队**　7 人，A 为唯一上台主讲人，G 独立负责 PPT 制作和整合
- **当前阶段**　规划与开工准备。真实模型、授权素材和实测结果均待组内准备。

## 1. 我们要做什么

做一个从英语视频到中文发布包的自动化工具，面向语音清楚的讲座、教程和访谈。翻译智能体写中文字幕与口播稿，审校智能体检查原文和译文，中文编辑智能体生成标题、简介与封面文案。LangGraph 把三个智能体和语音、视频工具编排起来。

人工处理这类视频时，术语需要全片一致，中文配音必须放进原来的说话时段，长任务中断后还要知道哪些结果可以复用。项目重点用可观察的返工和续跑解决这些问题。

| 项目 | 首版目标 |
|---|---|
| 输入 | 本地 MP4 或已登记的 YouTube 链接。链接按视频 ID 匹配团队有权读取的 HTTPS 原片地址 |
| 输出 | 中文配音 MP4（保留原画面，烧录中英双语字幕）、双语 SRT、中文封面 JPG、发布文案和运行报告，打包为 ZIP |
| 声音 | 一至两人交替发言。双人使用两种普通话系统音色，同一个人全片保持一致。成片用中文配音替换原混音 |
| 首版边界 | 语音清楚的英语视频。声音克隆、背景声分离、口型同步、重叠发言精细处理与网页界面留作后续 |

## 2. 开发顺序

| 阶段 | 做什么 | 过关条件 |
|---|---|---|
| **D1–D3 · 模拟闭环** | 先冻结分段和产物接口。用人工写好的英文分段、模拟译文和合成 WAV 作为测试输入。LangGraph 先跑通正常路径、错译退回、配音超时退回、中断续跑和打包 | 无模型密钥即可复现。能指出哪一段被退回、为什么重做，以及续跑复用了哪些结果 |
| **D4–D5 · 接真实模型** | 替换模拟适配器，依次接入英文转写与说话人区分、文本 API、普通话 TTS。先跑短片，再用约 10 分钟主样片做双入口验收 | 本地和登记链接分别输出完整发布包。双人短片能稳定切换音色 |
| **D6–D10 · 压测与汇报** | 跑 30 和 60 分钟压力测试、续跑和对照评测。D8 冻结演示版本，D9–D10 完成 PPT 与两次完整彩排 | 展示真实成片、报告和日志。压力测试按实测情况记录完成或失败 |

授权素材、真实模型和账号权限由对应组员在 D1 起并行准备。它们是第二阶段的输入，模拟阶段可以先开工。D1 同时检查演示机的 FFmpeg 是否支持 `subtitles` 滤镜和中文字体。

## 3. 工作流与模块约定

**读入素材 → 英文转写与说话人区分 → 分块翻译 → 审校 → 配音测时 → 中文编辑 → 合成与打包**

| 环节 | 输入与输出 |
|---|---|
| 转写与分段 | 用全片毫秒时间轴生成 `segment_id / speaker_id / start_ms / end_ms / en`。先确定说话人，再在自然句边界切为约 60–90 秒的翻译块。相邻块共享术语表和少量上下文 |
| 翻译与审校 | 翻译补充 `zh_subtitle / zh_dub`。审校返回问题片段 ID、原因和返工建议。任何智能体都沿用已有 ID 和时间戳 |
| 配音与返工 | TTS 输入为口播稿和说话人音色，输出音频与实测时长。短于时间窗时补静音，超时可最多加速到 1.15 倍，仍超时则只退回这一段重写和复审。每段最多两次内容返工 |
| 续跑与成片 | LangGraph 用本地 SQLite 保存图状态，磁盘保存各块产物。续跑复用已完成结果，并校验音频对应的文本、模型和音色。仍有待复核问题时保留报告，通过后再生成正式 ZIP |

计划工具链为 Python 3.11、LangGraph、Pydantic、faster-whisper、pyannote Community-1、百炼千问、CosyVoice、Pillow、FFmpeg/ffprobe。CLI 计划提供 `run --input <路径或链接>` 和 `resume --job <任务ID>`。模拟与真实适配器沿用相同数据结构。

## 4. 七人分工

表中的 A–G 是七名真实组员，翻译、审校和中文编辑则是软件智能体。组内启动时把 A–G 对应到姓名和 GitHub 用户名。

| 角色 | 交付物与责任 | 先学什么 |
|---|---|---|
| **A · 技术集成与唯一主讲人** | LangGraph 主图、模块接口、CLI、续跑。全程参与 B–E 的联调，亲自跑正常与异常用例，并与 F 复现长任务中断。上台负责讲解、操作和答疑 | 状态图、条件路由、检查点、端到端调试 |
| **B · 素材与语音识别** | 本地与链接入口、素材登记、带时戳转写、说话人标签及全片时间轴 | ffprobe、ASR、说话人区分、词级时间戳 |
| **C · 翻译与审校** | 两个智能体、术语表、结构化结果、定向返工 | Prompt、Pydantic、术语一致性与错漏译检查 |
| **D · 配音与同步** | 双音色映射、TTS、实测时长、音频缓存和音轨组装 | TTS、PCM/WAV、FFmpeg 滤镜 |
| **E · 字幕、封面与成片** | 中文编辑智能体、双语字幕、封面和发布包 | SRT/ASS、中文字体、Pillow、H.264/AAC |
| **F · 测试与评测** | 模拟故障、样片标注、译文对照、压测结果表 | pytest、模拟 API、盲评与指标统计 |
| **G · PPT 与演示材料** | **唯一 PPT 制作者**。收集证据，统一结构、图表、排版、视频和导出。协调彩排并准备备用录屏 | 图表、演示文稿、视频播放与计时 |

A–F 各给 G 一份模块材料，包含模块目标、一张图或一段日志、一个实际问题与处理结果。F 提供评测数据和原始记录。A 核对技术表述、编排讲述顺序并独立完成整场彩排。G 将材料整合到同一份 PPT。

## 5. 样片与验收

| 样片 | 验收项 | 记录方式 |
|---|---|---|
| 约 10 分钟英文讲座 | 硬验收。本地 MP4 和登记的 YouTube 链接分别产出完整发布包 | 任务 ID、成片检查、字幕、封面和来源 |
| 约 30 分钟英文讲座 | 全流程压测。处理中主动停止一次再续跑 | 已完成块复用情况、耗时、API 调用量和失败位置 |
| 约 60 分钟英文讲座 | 全流程压测 | 实际完成情况、各阶段耗时、调用量、失败位置和原因 |
| 约 2–3 分钟双人访谈或教程 | 产出成片并抽查至少 10 处发言交接 | 说话人归属、同一人音色一致性、字幕与配音同步 |

F 与另一名组员从片头、中段和片尾共抽 20 段盲评。使用相同英文转写、文本模型和音色，对比单次翻译直接配音与审校加定向返工。记录错漏译、术语错误、配音超时、返工次数、耗时和 API 调用量。汇报时注明哪些是模拟验证，哪些是真实样片实测。

## 6. 项目管理与排期

- **仓库**为私有的 `AchiDilyar/english-video-localizer`。`project/` 是本地仓库根目录。组员加入后在对应 Issue 认领任务，按模块建功能分支，通过 PR 合并到 `main`。每个 PR 至少一名队友审核，接口变更由 A 参与审核。
- **进度**在 Issue 里更新。开工标记 `status: in progress`，卡住标记 `status: blocked` 并写明需要谁解决。每条任务用 PR、可运行命令、日志或评测结果作为完成证据。
- **材料**只提交源码、锁文件、测试与文档。密钥、模型权重、原始素材、检查点和成片留在本地或团队授权空间。G 负责收集发布用的正式材料。

| 时间 | 团队动作 |
|---|---|
| **D1** | 定 A–G 人选，认领 Issue，冻结分段接口。B/F 确认候选样片及授权，C/D 确认模型接入资源 |
| **D2–D3** | 模拟阶段模块并行开发，A 主导联调，F 验证异常路径，G 搭好 PPT 结构 |
| **D4–D5** | 分步替换真实适配器，跑通 10 分钟双入口及双人短片，启动 30 分钟任务 |
| **D6–D7** | 完成 30 分钟中断续跑并启动 60 分钟压测，F 做对照评测，G 收齐模块材料 |
| **D8** | 冻结演示版本，在第二台机器复跑。归档成片、日志、评测数据与备用录屏 |
| **D9–D10** | G 导出 PPT，A 独立完整彩排两次，其中一次模拟网络失败并切换备用材料 |

## 7. 18 分钟课堂展示

PPT 封面统一使用《基于多智能体协作的英文视频本地化系统》。**A 一人负责上台。** G 交付最终 PPT 和可独立播放的备用材料。现场启动已登记的任务，展示进度和日志，再播放同一任务已经完成的成片节选。

| 时长 | 内容 |
|---:|---|
| 2 分钟 | 任务背景、选择原因、目标与七人分工 |
| 3 分钟 | LangGraph、三个智能体及其协作方式 |
| 5 分钟 | 三个难题及处理案例，涵盖说话人一致性、定向返工、时间轴与续跑 |
| 4 分钟 | 链接启动、返工日志、讲座成片和双人配音节选、发布包 |
| 3 分钟 | 10、30、60 分钟运行结果与对照实验，解释收益与开销 |
| 1 分钟 | 经验、限制与反思 |
